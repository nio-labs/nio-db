NioDB Documentation

The Agentic DB that works. A single-binary, ultra-lightweight database with pure-Rust SIMD vector search, multi-agent multiplexing, and natural-language query planning.

1. Quickstart & Installation

NioDB runs as a standalone single-binary server. Zero heavyweight dependencies, zero external database servers.

Run instantly via npx

npx @nio-labs/nio-db

Or build and run from source

npm install --omit=optional
cargo build --release --locked
node bin/niodb.cjs

On first launch, NioDB initializes a local data directory (default ./niodb) and listens on http://127.0.0.1:7432.

CLI Flag / OptionDescription
--dir <path>Set custom database storage directory.
--listen <ip:port>Override local bind address (default 127.0.0.1:7432).
--yesAccept all first-run setup defaults without prompts.
NIODB_NO_INSTALL_NIO=1Skip automatic Nio CLI installation.
NIODB_CORS_ORIGINSComma-separated list of allowed CORS origins.

2. Client SDKs

NioDB provides zero-dependency, ultra-lightweight client SDKs for JavaScript/TypeScript and Python.

JavaScript / TypeScript (@nio-labs/nio-db.js)

npm install @nio-labs/nio-db.js

Standard JSON Document Operations (Non-Vector)

import { createNioDB } from "@nio-labs/nio-db.js";

// Initialize with client-token and secret-token combination (or direct token)
const db = createNioDB({ 
  url: "http://127.0.0.1:7432", 
  clientToken: "niodb_client_...",
  secretToken: "niodb_secret_..." 
});
const users = db.collection("users");

// 1. Insert Document (with optional TTL in seconds)
const user = await users.insert({ name: "Alex Rivera", role: "admin", status: "active" }, { ttl: 86400 });

// 2. Read & List with Pagination
const profile = await users.get(user.id);
const page = await users.find({ limit: 25 });

// 3. Update / Patch Document
await users.update(user.id, { role: "superadmin", last_login: Date.now() });

// 4. Bulk Operations (Insert, Update, Delete)
await users.insertMany([
  { name: "Beatrix", role: "developer" },
  { name: "Carlos", role: "analyst" }
]);
await users.updateMany([{ id: "art_1", status: "verified" }]);
await users.deleteMany(["art_2", "art_3"]);

// 5. Delete Document
await users.delete(user.id);

// 6. SQL Query Studio
const { items } = await db.query("SELECT * FROM users WHERE role = 'admin'");

Vector & Semantic Search (Optional)

// Pure-Rust SIMD Cosine Distance Vector Search (No external vector DB needed)
const knowledge = db.collection("knowledge_base");
await knowledge.insert({
  text: "High-performance vector embeddings",
  embedding: [0.082, 0.491, 0.122, 0.941]
});

const matches = await knowledge.searchVector({
  vector: [0.082, 0.491, 0.122, 0.941],
  topK: 5,
  minScore: 0.75
});

3. Authentication & Tokens

NioDB uses standard Bearer tokens for all protected HTTP endpoints.

During initial setup, two secure credentials are created in your data directory: client-token and secret-token. Bearer authentication supports combining both credentials (<client-token>:<secret-token>) or using your client token directly.

CLIENT_TOKEN=$(cat ./niodb/client-token)
SECRET_TOKEN=$(cat ./niodb/secret-token)
NIODB_TOKEN="${CLIENT_TOKEN}:${SECRET_TOKEN}"

curl http://127.0.0.1:7432/api/v1/status \
  -H "Authorization: Bearer $NIODB_TOKEN"
Security Tip: Combining client-token:secret-token verifies both public client identity and private signing authority. For client web/mobile applications, register end users via POST /auth/register and use scoped session tokens from POST /auth/login.

4. Records, CRUD & Bulk Operations

A record is a JSON document stored in an append-only collection. NioDB assigns unique IDs, revisions, timestamps, and verifies SHA-256 integrity. Full CRUD and bulk batch operations are supported.

POST /api/v1/records — Insert Record

curl -X POST http://127.0.0.1:7432/api/v1/records \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: task-create-001" \
  -d '{
    "collection": "tasks",
    "data": {
      "title": "Review release build",
      "priority": "high",
      "ttl": 3600
    }
  }'

GET /api/v1/records/:id — Read Record

curl http://127.0.0.1:7432/api/v1/records/art_123 \
  -H "Authorization: Bearer $NIODB_TOKEN"

PATCH /api/v1/records/:id — Update Record

Atomically updates and merges record data, incrementing the revision counter.

curl -X PATCH http://127.0.0.1:7432/api/v1/records/art_123 \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "priority": "urgent",
      "status": "in_progress"
    }
  }'

DELETE /api/v1/records/:id — Delete Record

Appends a tombstone deletion event to the journal, removes from in-memory index, and cleans the artifact projection.

curl -X DELETE http://127.0.0.1:7432/api/v1/records/art_123 \
  -H "Authorization: Bearer $NIODB_TOKEN"

POST /api/v1/records/bulk — Bulk Operations (Batch)

Perform high-throughput bulk inserts, updates, and deletes in a single request.

1. Bulk Insert:

curl -X POST http://127.0.0.1:7432/api/v1/records/bulk \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "collection": "tasks",
    "action": "insert",
    "records": [
      { "title": "Index vector embeddings", "status": "pending" },
      { "title": "Run storage compaction", "status": "pending" }
    ]
  }'

2. Bulk Update:

curl -X POST http://127.0.0.1:7432/api/v1/records/bulk \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "update",
    "records": [
      { "id": "art_1", "data": { "status": "completed" } },
      { "id": "art_2", "data": { "status": "completed" } }
    ]
  }'

3. Bulk Delete:

curl -X POST http://127.0.0.1:7432/api/v1/records/bulk \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "delete",
    "ids": ["art_1", "art_2"]
  }'

GET /api/v1/records — List & Pagination

curl "http://127.0.0.1:7432/api/v1/records?collection=tasks&limit=50" \
  -H "Authorization: Bearer $NIODB_TOKEN"

List requests support page limits from 1 up to 1,000 records per request, using cursor-based pagination.

5. Vector & Semantic Search

NioDB features a native, pure-Rust SIMD-friendly vector similarity engine. No external vector database or C++ dependencies required.

POST /api/v1/records/search — SIMD Vector Search

curl -X POST http://127.0.0.1:7432/api/v1/records/search \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "collection": "embeddings",
    "vector": [0.082, 0.491, 0.122, 0.941],
    "top_k": 5,
    "min_score": 0.75
  }'

Vector Search Response:

6. SQL Query Studio (AlaSQL Engine)

Run safe, restricted, parameterized SQL queries across your collections. Collections automatically act as SQL tables with top-level JSON fields exposed as queryable columns.

POST /api/v1/query — Execute SQL

curl -X POST http://127.0.0.1:7432/api/v1/query \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "sql": "SELECT id, title, status FROM tasks WHERE status = ? ORDER BY id DESC LIMIT 50",
    "parameters": ["pending"]
  }'

7. Natural Language Queries (Ask Nio)

Ask natural-language questions about stored data. Nio formulates bounded read plans, executes authorized queries, and provides grounded answers.

POST /api/v1/assist — Natural Query

curl -X POST http://127.0.0.1:7432/api/v1/assist \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"message": "How many tasks are currently pending in our database?"}'

10. Model Context Protocol (MCP) & Agent Tools

NioDB natively speaks the JSON-RPC Model Context Protocol (MCP) and exports standardized tool-calling schemas for OpenAI, Anthropic, and LangChain.

POST /mcp — Standard MCP JSON-RPC

curl -X POST http://127.0.0.1:7432/mcp \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "tools/list", "params": {}}'

GET /api/v1/agent/tools — Export Agent Schemas

curl http://127.0.0.1:7432/api/v1/agent/tools \
  -H "Authorization: Bearer $NIODB_TOKEN"

11. Files & Blob Storage

Store assets, PDFs, images, and binary attachments in isolated buckets with automatic deduplication.

POST /api/v1/storage/:bucket/upload — Upload File

curl -X POST http://127.0.0.1:7432/api/v1/storage/documents/upload \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -F "file=@./document.pdf"

GET /api/v1/storage/:bucket/:id — Download File

curl http://127.0.0.1:7432/api/v1/storage/documents/fil_123 \
  -H "Authorization: Bearer $NIODB_TOKEN" -o output.pdf

12. Live Events, SSE & Webhooks

Publish real-time events to connected clients via Server-Sent Events (SSE) and deliver HMAC-SHA256 signed webhooks.

POST /api/v1/events — Publish Event

curl -X POST http://127.0.0.1:7432/api/v1/events \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "record.created", "data": {"record_id": "art_123"}}'

GET /api/v1/events/stream — SSE Event Stream

curl -N "http://127.0.0.1:7432/api/v1/events/stream?name=*" \
  -H "Authorization: Bearer $NIODB_TOKEN"

13. User Accounts & Session Tokens

Built-in user directory with salted PBKDF2 password hashing and 7-day bearer session tokens.

Register & Login

# 1. Register user (Backend token required)
curl -X POST http://127.0.0.1:7432/auth/register \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"username": "developer", "password": "SuperSecretPassword123"}'

# 2. Login from client (Returns access_token)
curl -X POST http://127.0.0.1:7432/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "developer", "password": "SuperSecretPassword123"}'

14. Storage Compaction & Maintenance (Vacuum)

NioDB provides zero-downtime atomic journal compaction to reclaim disk space, remove expired TTL records, and clean deleted files.

POST /api/v1/admin/vacuum — Trigger Vacuum

curl -X POST http://127.0.0.1:7432/api/v1/admin/vacuum \
  -H "Authorization: Bearer $NIODB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}'

Vacuum Response:

{
  "success": true,
  "stats": {
    "initial_bytes": 14285820,
    "compacted_bytes": 2840120,
    "active_artifacts": 1250,
    "active_users": 15,
    "active_files": 48,
    "purged_expired": 320
  }
}

15. Resource Limits & Capacities

NioDB offers generous resource limits while maintaining sub-millisecond local in-memory execution and minimal disk footprint.

Resource Supported Limit Details
Records Capacity Millions of records (16 MiB per record, 64 GiB+ journal) Unbounded in-memory pure-Rust BTree indexing with in-place zero-downtime atomic vacuum compaction.
Pagination Up to 1,000 items per page Fast cursor-based pagination across all collection and file list endpoints.
Vector Embeddings SIMD Cosine Distance (Arbitrary dimensions) Sub-millisecond pure-Rust dot product search over vector embeddings with zero external C++ vector DBs.
SQL Queries 64 KiB input, 1,000 output rows, 15s timeout Restricted read-only SQL with 64 MiB query execution buffer powered by bundled AlaSQL engine.
Nio Natural Query 4 concurrent requests, 60s default timeout (1–300s) Bounded natural language query planning via Nio CLI.
Files & Blobs 64 MiB per file, 100 GiB per workspace, 1,000,000 files Content-addressable storage with SHA-256 deduplication and Range request support.
Users & Sessions 100,000 users, 1,000,000 active sessions Salted PBKDF2 hashing, 7-day bearer sessions with instant revocation across restarts.
Live Events 64 KiB payload, 100/sec, 1,024-event buffer Server-Sent Events (SSE) broadcast channel with gap detection.
Webhooks & Workers 64 webhooks, 64 TypeScript workers HMAC-SHA256 signed deliveries and isolated Node worker processes.
